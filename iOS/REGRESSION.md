# iOS 输入法行为契约与回归清单

本文逐条记录 iOS「是语输入法」开发中提出过的需求和发现过的回归。后续修改候选、组合状态、触摸、引擎或模型时，必须逐项检查；不能用修复单个示例的硬编码替代通用机制。

状态说明：

- **已实现**：已有实现，但仍需按本清单回归。
- **测试覆盖**：已有自动测试。
- **待完善**：需求明确，但当前实现尚未完全满足。
- **真机必测**：模拟器或单元测试不能替代真机验证。

## 1. 工程、隐私和输入方案

1. Xcode 工程以 `iOS/project.yml` 为唯一工程源，不提交生成的 `iOS/Sime.xcodeproj/`。
2. 键盘必须完全离线运行，不申请“完全访问”，不得上传或记录用户输入正文。
3. 系统只安装一个键盘扩展，名称为“是语键盘”；宿主 App 名称为“是语输入法”。
4. 全拼和微软双拼通过宿主 App 开关切换，并通过 App Group 共享设置。
5. 切换输入方案后键盘必须重建对应 Composition，不能混用上一方案状态。
6. 模型和 ncnn runtime 必须位于 Keyboard Extension 自身资源/链接范围内，不能依赖宿主 App 进程。

## 2. 基础拼音与候选召回

7. 普通输入必须使用真实 Sime 离线模型，不得退化成小型硬编码词表（模型缺失的开发 fallback 除外）。
8. 空格提交当前整句首选；不能遗留最后一个拼音字母。
9. 回车在有组合时按用户原始按键直接提交英文/拼音，不把拼音转换成中文；无组合时才向宿主发送换行。
10. 第一行句末确认按钮提交中文整句，但不额外插入换行。
11. 普通候选顺序为完整长句/长词在前，短词和单字在后。
12. 单字候选必须完整召回，不能被 Top-20、整句 beam 或 UI 首屏截断；例如低频同音字“删”必须可达。
13. Layer 1 返回覆盖全部拼音的完整路径；Layer 2 返回从当前位置消费部分拼音的短词和单字。
14. `extra` 是 Layer 1 调用参数；当前 iOS 正常解码使用 `extra = 2`，即最多三条完整候选。
15. Layer 1 和 Layer 2 文本必须去重。
16. macOS 当前历史实现会额外合并 `DecodeStr(..., num: 9)`；iOS 重构时不能误把这个历史行为描述为单一候选格。
17. 候选不能通过针对具体文字的白名单、黑名单或“强塞首选”修复。

## 3. 第一行逐字/逐词改选

18. 第一行显示当前整句，每个字都可以点击，包括已经改选过的字及其前后任意位置。
19. 点击第一行某字后，第二行只显示从该位置开始的可替换内容；不能显示固定前缀。
    - 示例：第一行 `你好世界`，点“世”，第二行显示 `世界、时间…`，不能显示 `你好世界、你好时间…`。
20. 候选排序必须考虑点选位置之前的当前文字，不能把尾部当成新句独立解码。
    - 反例：`性价比` 点“价”，不能因为只解 `jia'bi` 而把“假币”错误排在“价比”之前。
21. `性价比` 点“价”的真实引擎回归契约：第二行开头应为 `价比、假币、家比…`（模型更新时若分数变化，必须人工审查而非静默改测试）。
22. 第二行必须同时包含长尾部、短词和完整单字候选；不能只剩完整路径，也不能把单字表在 Swift 中临时拼接成另一套机制。
23. 正常输入与改选必须复用同一套 Layer 1 / Layer 2 候选提取逻辑；改选只增加起始列、上下文和约束参数。
24. 点击位置之前的文字只参与约束和排序，不应出现在第二行候选显示文本中。
25. 候选的 `units` 和 `consumed` 必须反映可替换尾部，而不是完整句的消费范围。
26. 选择单字后只替换对应音节，并自动推进到下一个未处理音节。
27. 选择多字词后消费其完整音节范围，并自动推进到该词之后。
28. 第一行当前活动位置显示用户实际输入的按键：
    - 全拼显示用户输入的全拼及分隔符；
    - 微软双拼显示用户输入的双拼码；
    - 不得把双拼码翻译成全拼后再显示。
29. 点击首字时没有固定中文前缀，候选首字允许变化；点击中间字时前缀必须保持。
30. 低分路径应通过通用 beam/score 机制控制，不能针对“珈币”等具体词硬编码过滤。

## 4. 多锚点组合框架（当前最高优先级）

31. 用户明确选择过的字或词必须成为锚点；继续输入时不得被后续整句重解码改写。
32. 所有第一行字符始终可点击，不能因为先改了中间字而禁止点击前面的字。
33. 锚点必须是多个独立、音节对齐的约束，不能把“点选位置之前所有文字”合并成一个不可编辑固定前缀。
34. 点击任意位置时，该位置之前的当前文字用于候选排序；但只有用户明确选过的范围是永久锚点。
35. 再次点击更早或更晚位置时，所有不与新选择重叠的已有锚点都必须保持，不得连带调整。
36. 新选择与旧锚点重叠时，只替换被覆盖范围；不能清空全部锚点。
37. 锚点数据必须保存原始按键范围、音节范围、显示文字和 token；不能用汉字字符串长度反推拼音消费范围。
38. 字候选和词候选必须走同一个锚点状态转移。
39. GRU 只能在满足全部锚点硬约束的合法路径之间重排，不能改变锚点。
40. 锚定后继续追加输入、退格、移动 marked-text 光标以及锁屏恢复都必须保持一致状态。
41. 当前自动测试包括：
    - `xingjiabi → 性价比 → 点价` 的候选契约；
    - 选择单字后继续输入仍保持锚点；
    - 选择多字词后继续输入仍保持其 source range。
42. **待完善**：当前框架仍需升级为完整的多锚点、任意回点模型；此项完成前不能把锚定标记为最终完成。

## 5. 候选栏触摸和布局

43. 第一行为整句逐字按钮，第二行为横向滚动候选。
44. 第二行使用 UILabel + 候选栏统一点击手势 + 原生 UIScrollView；不能恢复为会抢滚动手势的候选 UIButton。
45. 点击候选与横向拖动必须互不冲突。
46. 候选渲染后必须立即更新 `contentSize`，第一帧即可长距离滚动。
47. 候选文本宽度按实际显示文字计算，不能用隐藏前缀或原始 candidate text 计算错误宽度。
48. 当前真机调试布局参数：顶部 `-6pt`、第一行 `28pt`、第一行按钮最小 `24pt`、间距 `3pt`、第二行间距 `6pt`。

## 6. Marked text、光标和编辑

49. 组合期间使用 marked text，并同步 `selectedRange`。
50. 点击宿主中已上屏/marked 的拼音应定位组合光标，不能让整段拼音消失。
51. 宿主只提供 `documentContextBeforeInput` 或只提供 `documentContextAfterInput` 时，也应尽可能定位光标；不能要求两侧同时非 nil。
52. 在拼音中间插入字母后，候选和 marked 光标必须对应新位置。
53. 在拼音中间退格只删除光标前一个原始按键。
54. 锁屏、切 App 或扩展重建后，从 `pendingRaw` / `pendingCommitted` 恢复组合；不能丢失拼音。
55. 恢复 marked text 时要防止 `textDidChange` 重入循环。
56. **真机必测**：备忘录等宿主会临时 unmark 组合，键盘必须恢复，而不是清空组合。

## 7. 空格、删除和回车

57. 空闲状态长按空格进入宿主光标移动模式；组合状态下不能误触发。
58. 进入空格光标模式时触发一次轻触感反馈。
59. 光标随手指位移细粒度连续移动；快速拖动不能漏掉跨越的字符步数。
60. 删除键支持长按连续删除，并在松开/取消时停止 timer。
61. 回车标题读取 `returnKeyType`，显示“发送、搜索、完成、前往、下一项、加入、继续、路线”等。
62. 有组合时按回车提交用户原始英文按键；不能转换中文，也不能额外换行。

## 8. 数字、标点和键盘页

63. 数字页输入数字后保持数字页。
64. 数字页输入标点后自动回字母页。
65. 中文标点至少正确映射分号 `; → ；`；完整中文/半角标点策略仍在 TODO。
66. 标点提交前先提交当前组合。

## 9. 微软双拼

67. 微软双拼转换必须表驱动并有完整测试，不能只按用户反馈逐项打补丁。
68. 已知必须覆盖：`wo`、`go`、`ys`、`or`、零声母、`v` 韵母记法。
69. 已有测试需持续覆盖 `wo`、`xcgo`、`xigw`、`gv`、`js`、`ys`、`gd`、`oa`、`ol`、`oo`、`or`、`nv`、`lt`、`lr`、`lp`。
70. 双拼候选消费长度按音节映射回原始双拼按键，不能直接使用全拼字节数。
71. 双拼逐字改选活动标签必须显示原始两键码。

## 10. 联想和宿主正文上下文

72. 上屏后使用 Sime `NextTokens` 做离线联想，不得用硬编码词表。
73. 点击联想词后更新短期 context，并可连续联想。
74. 正常拼音解码和联想都应考虑宿主光标前正文，而不只考虑本键盘本次上屏的 token。
75. 宿主正文通过 Sime `Cutter` 转为 token，全程本地处理。
76. `documentContextBeforeInput` 中包含当前 marked 前缀时，必须先移除 marked 部分，不能把未提交拼音当正文 context。
77. 分词器不能在切换键盘或点击第一行时造成扩展内存峰值和闪退。
78. 分词器大型索引应延迟创建，并设计缓存/生命周期上限。
79. 宿主未提供正文时，本键盘已有 token context 作为 fallback。
80. context 长度最终应使用 `sime_context_size`，不能永久硬编码 32。
81. 句末标点后应清空联想 context（待完善）。

## 11. GRU / ncnn

82. iOS 使用 CPU-only ncnn XCFramework，并定义 `SIME_ENABLE_NCNN=1`。
83. `gru.embedding.i8`、pinyin/t9 `.param` 和 `.bin` 必须打包进 Keyboard Extension。
84. ncnn XCFramework 是本地生成物，不提交；新环境先运行 `iOS/scripts/build-ncnn-xcframework.sh`。
85. Simulator arm64/x86_64 与真机 arm64 都必须可链接构建。
86. GRU 只做候选重排，不负责数字/字母键盘页选择，也不能突破组合锚点硬约束。

## 12. 闪退与资源回归

87. 选择“是语键盘”时不能出现巨大空白按键后闪退。
88. 输入普通拼音不能闪退。
89. 点击第一行任意字不能因临时创建 `Cutter` 大索引而触发扩展内存终止。
90. 引擎资源初始化必须考虑 iOS Keyboard Extension 的紧内存限制；桌面端可接受的常驻索引不能直接照搬。

## 13. 自动测试和发布前命令

Sime 引擎回归：

```bash
cmake -S require/Sime -B /tmp/sime-test \
  -DSIME_BUILD_TOOLS=OFF -DBUILD_TESTING=ON
cmake --build /tmp/sime-test
ctest --test-dir /tmp/sime-test --output-on-failure
```

iOS 单元测试：

```bash
cd iOS
xcodegen generate
xcodebuild -project Sime.xcodeproj -scheme Sime \
  -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.4' test
```

真机/设备构建：

```bash
xcodebuild -project Sime.xcodeproj -scheme Sime \
  -sdk iphoneos -configuration Debug build
```

发布前还必须按第 3、4、6、10、12 节做真机手工回归，尤其是：

```text
性价比 → 点价 → 查看第二行 → 选单字 → 继续输入
→ 再点前面的“性” → 原有不重叠锚点仍保持
```
